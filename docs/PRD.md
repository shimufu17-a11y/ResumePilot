## 2. 产品概述

ResumePilot 是一款面向秋招和校招场景的本地优先求职表单填写助手。它帮助用户维护公共个人信息与多个求职方向档案，在招聘平台、企业招聘官网和研究院所招聘系统中识别并填写重复字段、匹配附件、辅助回答开放问题、逐页导航，并在用户亲自确认提交后记录投递结果。

首要使用场景包括：

1. 使用“雷达岗位”档案投递中电科研究所及航天院所相关岗位。
2. 使用“Agent 开发岗位”档案投递互联网、科技和制造企业的 AI / Agent 开发岗位。
3. 在两类岗位之间快速切换简历、项目经历、技能重点和问题答案，同时复用联系方式、教育信息等公共资料。

产品不追求无人值守海投。所有最终提交操作必须由用户本人完成。

## 3. 产品目标

### 3.1 核心目标

1. 减少跨招聘网站重复录入个人信息、教育经历、项目经历和证书等内容的工作量。
2. 支持不限数量的求职档案，并保证不同档案之间不会错误串用经历、答案或简历附件。
3. 对标准网页表单提供通用填写能力，对重点网站和常见招聘系统提供专用适配。
4. 在不依赖云端后端的情况下完成档案、附件、答案库和投递记录管理。
5. 使用可选 AI 辅助简历解析、JD 分析、档案推荐和答案起草，但不允许 AI 编造事实。
6. 作为公开 GitHub 项目发布，允许其他用户安装、使用和贡献网站适配器。

### 3.2 成功标准

1. 在已验证兼容的网站中，至少 80% 的常见重复字段可由插件正确给出填写候选；已支持字段的最终填充值准确率达到 95% 以上。
2. 用户可在 3 次交互以内完成求职档案切换、当前页预览和一键填写。
3. 未完成必填项、敏感项待确认或页面用途不明确时，插件停止自动进入下一步。
4. 插件在任何情况下都不主动触发最终投递、申请确认或不可逆提交。
5. 不配置 AI 时，档案管理、附件管理、规则匹配、表单填写、逐页导航和投递记录仍可完整使用。

## 4. 用户与典型场景

### 4.1 目标用户

- 需要在多个平台和企业官网参加秋招、校招的学生或应届毕业生。
- 针对不同岗位方向准备了多份简历和不同项目叙述的求职者。
- 重视个人数据隐私，不希望将完整档案长期保存到第三方服务器的用户。

### 4.2 典型流程

1. 用户安装插件，创建主密码并进入本地资料库。
2. 用户导入 PDF 或 DOCX 简历，插件在本地提取文本并生成结构化候选字段。
3. 用户逐项审阅解析结果，将公共资料写入公共档案，将方向性内容写入“雷达岗位”或“Agent 开发岗位”档案。
4. 用户为各档案绑定相应简历 PDF，并维护成绩单、证件照、证书等附件。
5. 用户登录招聘网站并打开职位申请页面。
6. 插件读取页面字段和 JD，推荐求职档案；用户确认或切换档案。
7. 侧边栏展示计划填写的字段、来源、敏感级别和未解决项目。
8. 用户执行“填写当前页”或“填写并进入下一步”。每个新页面重复预览与确认流程。
9. 到达最终提交页后插件停止。用户检查并亲自点击提交。
10. 插件检测提交行为或成功页面，经用户确认后写入投递记录。

## 5. 范围定义

### 5.1 首版范围

- 本地加密资料库与自动锁定
- 公共档案与多个求职方向档案
- PDF / DOCX 简历导入、文本提取和结构化候选结果确认
- 简历及常用证明材料的附件资料库
- 公共、求职方向、公司和单次使用四级答案库
- 中英文网页表单识别、填写预览和执行
- 常见输入框、文本域、单选、多选、下拉框、日期及常见自定义组件支持
- 求职档案自动推荐及人工确认
- 可选的 OpenAI 兼容 AI 接口
- JD 分析、匹配点提示及有事实约束的答案起草
- 安全的逐页导航与最终提交保护
- 本地投递记录及手动状态维护
- 网站字段手动映射与本地规则记忆
- 加密备份导入导出及显式未加密导出
- 中英文界面切换
- Chrome 与 Edge 支持
- GitHub 源码、构建产物、安装说明、隐私说明及贡献指南

### 5.2 明确不在首版范围

- 职位聚合、职位爬取或自动搜索职位
- 批量海投、无人值守填写或自动最终提交
- 自动登录、短信验证、验证码或人机验证绕过
- 面试进度或招聘网站状态的后台自动抓取
- 自动修改原始简历 PDF / DOCX 排版
- 自动捏造、夸大或补全不存在的经历、论文、专利、成绩和奖项
- 云端账号、跨设备云同步或项目自建后端
- 扫描版 PDF 的 OCR 识别（可作为后续能力）
- 首版直接发布 Chrome Web Store 或 Edge Add-ons；稳定后另行评估

## 6. 网站兼容策略

### 6.1 兼容层级

插件采用三层兼容架构：

1. **通用表单引擎**：根据 `label`、`name`、`id`、`placeholder`、ARIA 属性、附近文本和控件类型识别字段，尝试兼容任何结构规范的中英文招聘表单。
2. **招聘系统适配器**：针对 Moka、北森、前程无忧校招系统、Workday、SAP SuccessFactors 等被多家企业复用的招聘系统处理自定义组件和页面流程。
3. **网站专用适配器**：针对重点平台、企业和研究院所处理特有字段、动态页面、附件区和下一步按钮。

适配器必须与档案、AI、加密存储等核心逻辑解耦。新增网站原则上不修改核心填写引擎。

### 6.2 重点兼容目标

#### A. 研究所及航天院所

- 中电科 14 所
- 中电科 38 所
- 中电科 54 所
- 607 所
- 航天一院、二院、五院、八院

上述单位的实际招聘入口可能随招聘年份、集团统一门户或第三方供应商变化。适配阶段以用户提供的当期真实招聘网址为准。

#### B. 企业招聘官网

- 华为
- 比亚迪
- 京东
- 字节跳动
- 美团
- 拼多多
- TP-Link
- 理想汽车

其他知名企业通过通用引擎优先支持，并根据用户反馈和社区贡献增加专用适配器。

#### C. 主流招聘平台

- BOSS 直聘
- 牛客
- 智联招聘
- 前程无忧
- 猎聘

### 6.3 兼容状态定义

每个网站或招聘系统在兼容矩阵中标注以下状态之一：

- `通用`：仅由通用引擎处理，未做完整验证。
- `部分验证`：已验证核心文本字段，复杂组件或附件仍需人工操作。
- `已验证`：已在当期页面完成核心字段、附件区和逐页导航测试。
- `受限`：因登录、验证码、浏览器安全限制或网站反自动化机制只能半自动操作。
- `待修复`：网站改版后适配器暂时不可用。

公开发布时必须如实提供兼容矩阵，不使用“支持所有网站”等无法验证的承诺。

## 7. 功能需求

### FR-01 本地资料库与主密码

1. 首次启动时引导用户创建主密码。
2. 公共档案、求职档案、答案库、附件、站点规则、投递记录和持久化 API Key 均加密后存储。
3. 密钥由主密码派生，不以明文形式持久化；资料库锁定后从运行内存清除解密密钥。
4. 支持用户配置自动锁定时间。
5. 主密码不可找回。忘记主密码时只能清除并重新建立资料库，产品必须在创建密码和导出备份时明确提示。
6. 插件不得将真实用户资料写入日志、错误报告或 GitHub 仓库。

### FR-02 公共档案与求职档案

1. 用户可创建、复制、重命名、归档和删除任意数量的求职档案。
2. 公共档案至少覆盖：
   - 中英文姓名、手机号、邮箱和常用联系方式
   - 性别、出生日期、籍贯、生源地、现居地、户籍等基础信息
   - 政治面貌、民族、健康状况等院所常见字段
   - 教育经历、成绩、排名、主修课程
   - 实习、工作、项目、科研经历
   - 论文、专利、竞赛、奖项、证书、语言及技能
   - 求职地点、到岗时间、期望薪资、出差和调剂意向
3. 身份证号、详细住址、家庭成员、健康信息等标记为高敏感字段。
4. 求职档案继承公共资料，并能控制经历条目的包含、隐藏、顺序和方向性描述。
5. 每个求职档案可绑定默认简历、目标岗位关键词、技能重点、答案库和默认投递偏好。
6. 网站或公司可设置默认档案，但每次执行填写前必须显示并允许切换。

### FR-03 简历导入与解析

1. 支持导入可复制文本的 PDF 和 DOCX 文件。
2. 文件文本提取默认完全在本地完成。
3. 解析结果按字段展示候选值、来源片段和置信度；低置信度内容不得自动写入档案。
4. 用户必须审阅差异并确认后，解析结果才能保存。
5. 可选 AI 解析只能在用户确认发送范围后执行，并必须排除高敏感字段。
6. 原始简历文件不得进入源码仓库、示例数据或错误日志。

### FR-04 附件资料库

1. 支持管理简历 PDF、证件照、生活照、成绩单、学历/学位证明、语言及计算机证书、获奖证明、论文和专利材料。
2. 附件具有名称、类型、所属档案、标签、备注、更新时间等元数据。
3. 同一类型允许保存多个版本，并可为求职档案指定默认版本。
4. 插件根据文件上传区附近文本推荐附件，用户可在上传前确认或替换。
5. 在浏览器和网站允许时自动设置文件；无法安全设置时，应高亮上传区域并打开附件选择提示，不得静默失败。
6. 高敏感附件不得发送给 AI。

### FR-05 分层答案库

1. 答案保存范围包括：公共、当前求职方向、当前公司、仅本次使用。
2. 匹配优先级为：当前公司 > 当前求职方向 > 公共；仅本次答案不持久化。
3. 覆盖自我评价、求职动机、优势与不足、项目介绍、技能、证书、地点、薪资、到岗、调剂、出差、加班等常见问题。
4. 遇到未知问题时暂停，允许用户手动回答或请求 AI 起草，再选择是否保存及保存范围。
5. 答案应保留来源和最近修改时间；AI 生成内容必须明确标识并经用户确认。
6. 对有字数限制的字段，可基于原答案生成缩写候选，但不得删除关键事实或自动写入未经确认的内容。

### FR-06 页面识别与填写预览

1. 支持识别文本框、文本域、原生及常见自定义下拉框、单选、多选、日期、级联地区和文件上传区。
2. 识别逻辑综合字段标签、属性、上下文、页面步骤、网站规则和历史手动映射。
3. 填写前在侧边栏展示：页面字段、候选值、数据来源、置信度、敏感级别和是否必填。
4. 用户可逐项排除、修改候选值或将网页字段映射到其他档案字段。
5. 执行填写时正确触发网页框架所需的输入、变化和失焦事件。
6. 必填但无候选值、字段含义不明确或页面发生显著变化时，插件停止并提示用户。
7. 高敏感字段默认不填，每次使用均需单独确认，且不得将一次确认扩展为全局永久授权。

### FR-07 本地规则学习

1. 用户可选择网页字段并手动关联档案字段或答案。
2. 映射规则按网站、路径模式和控件上下文存储在本地。
3. 下次遇到相同或相似字段时显示已学习规则及来源。
4. 用户可查看、编辑、导出和删除已学习规则。
5. 本地学习仅代表映射记忆，不执行未经用户确认的在线模型训练或数据上传。

### FR-08 求职档案推荐与 JD 分析

1. 插件可读取当前职位标题和用户主动授权的 JD 内容。
2. 优先用本地关键词规则推荐档案；启用 AI 后可给出更完整的匹配分析。
3. 推荐结果包含推荐档案、匹配依据、突出项和缺失项。
4. 推荐结果不得直接触发填写；用户必须确认选择。
5. AI 可以建议突出哪些已有项目与技能，但不得修改原始简历文件或虚构事实。

### FR-09 可选 AI 能力

1. 支持用户配置 OpenAI 兼容的 Base URL、API Key 和模型名。
2. API Key 可选择仅保留在当前解锁会话，或随本地资料库加密保存。
3. 每次调用前展示将发送的数据类型和范围，用户确认后才发起请求。
4. 高敏感字段和高敏感附件永不发送给 AI。
5. AI 仅用于生成候选结果，包括简历字段候选、问题匹配、JD 分析、档案推荐和答案起草/压缩。
6. AI 结果必须以候选形式呈现，未经确认不得写入档案或网页。
7. AI 不可用、接口失败或额度不足时，应降级为本地规则模式，不影响核心填写流程。
8. 产品需提示第三方接口的数据处理风险；自定义 Base URL 由用户自行信任和负责。

### FR-10 安全逐页导航

1. 提供“填写当前页”和“填写并进入下一步”两个明确操作。
2. 自动进入下一步只能发生在用户本页主动触发后，不启动无人值守的跨页面循环。
3. 点击前必须确认当前页无未解决的必填项和敏感项。
4. 对“下一步、保存并继续”等可逆或非最终按钮进行白名单式识别。
5. 对“提交、确认投递、申请职位、完成申请”等最终动作进行拦截；含义不确定时一律不点击。
6. 验证码、人机验证、隐私协议和敏感意向选择必须交由用户处理。

### FR-11 投递记录

1. 记录公司、岗位、网站、职位链接、所用求职档案、开始填写时间、确认投递时间和备注。
2. 初始状态至少包含：填写中、已投递、笔试、面试、Offer、拒绝、放弃；除“填写中”和“已投递”检测外均由用户手动维护。
3. 用户亲自点击最终提交或页面出现成功提示后，插件弹窗询问是否记录为“已投递”。
4. 无法确认是否成功时保持“填写中”，不得自动推断为已投递。
5. 支持按公司、岗位方向、状态和时间筛选，并支持导出。
6. 首版不在后台登录招聘网站抓取状态。

### FR-12 备份、恢复与迁移

1. 默认导出使用主密码保护的加密备份，包含结构化资料、答案、规则、记录及用户选择的附件。
2. 允许用户在明确风险提示后导出未加密 JSON；附件可独立选择是否包含。
3. 导入前展示备份版本和内容摘要，并支持覆盖导入或合并导入。
4. 合并冲突必须由用户选择，不得静默覆盖现有档案。
5. 备份格式应带版本号并提供向后迁移机制。

### FR-13 中英文支持

1. 扩展界面提供简体中文和英文切换，默认跟随浏览器语言并允许手动覆盖。
2. 字段识别词典同时包含常见中英文招聘字段。
3. 求职档案允许同时维护中英文值或仅维护一种语言。
4. Workday、SuccessFactors 等英文系统中的标准字段应由通用引擎或专用适配器处理。

### FR-14 开源发布与隐私说明

1. 仓库采用 MIT License。
2. 仓库仅包含虚构的测试档案、附件和网页样例。
3. 提供 Chrome / Edge 开发者模式安装说明、构建说明、权限说明、数据删除说明和安全边界。
4. 提供网站适配器贡献指南、测试模板和兼容矩阵。
5. 首次公开发布提供可审计源码和版本化安装压缩包。

## 8. 交互与信息架构

### 8.1 侧边栏

侧边栏是填写场景的主界面，至少包含：

- 当前网站、页面步骤和兼容状态
- 当前职位及推荐求职档案
- 档案确认/切换入口
- 当前页字段预览、异常和敏感项提示
- “填写当前页”“填写并进入下一步”操作
- AI 分析和未知问题处理入口
- 最终提交保护提示

### 8.2 扩展弹窗

弹窗用于轻量操作：

- 查看资料库锁定状态
- 快速解锁
- 快速切换当前求职档案
- 打开侧边栏
- 查看当前页面是否可填写

### 8.3 管理页面

管理页面用于复杂编辑：

- 公共资料与求职档案
- 简历导入结果确认
- 附件资料库
- 答案库
- 投递记录
- 网站规则及兼容信息
- AI、安全、语言、备份和权限设置

## 9. 核心数据模型

| 实体            | 主要内容                                         |
| --------------- | ------------------------------------------------ |
| `Vault`         | 加密版本、密码派生参数、自动锁定设置             |
| `CommonProfile` | 公共基本信息及经历条目库                         |
| `JobProfile`    | 岗位方向、公共信息覆盖、经历选择与排序、默认附件 |
| `ResumeSource`  | 原始简历、提取文本、解析状态、字段来源           |
| `Asset`         | 加密附件、类型、标签、所属档案、元数据           |
| `Answer`        | 问题、答案、适用范围、事实来源、是否 AI 生成     |
| `SiteRule`      | 域名、路径模式、字段特征、映射目标、版本         |
| `Application`   | 公司、岗位、链接、档案、状态、时间线、备注       |
| `AIConfig`      | Base URL、模型名、加密 API Key、会话策略         |

求职档案通过引用和覆盖公共经历条目实现复用，避免复制两套个人基础信息后产生不一致。

## 10. 非功能需求

### 10.1 隐私与安全

- 默认本地优先，无自建后端，无遥测。
- 使用浏览器原生 Web Crypto 能力加密静态数据，具体算法和参数需在技术设计中记录并接受审查。
- 网络权限按需申请；AI 服务的域名权限仅在用户配置并调用时使用。
- 不注入远程代码，满足 Manifest V3 和扩展商店的内容安全策略。
- 日志不得包含档案值、附件内容、API Key 或完整 JD。
- 文档需说明：本地加密不能防御已控制用户设备、已解锁浏览器会话或恶意扩展。

### 10.2 兼容性

- 支持当前稳定版及前一个稳定版 Chrome 和 Edge。
- 以 Windows 使用场景为首要验证环境，同时避免依赖 Windows 专属扩展 API。
- 页面适配器异常不得导致档案损坏或阻塞其他网站的通用模式。

### 10.3 性能与可靠性

- 普通页面字段扫描和预览目标耗时不超过 2 秒，不包含 AI 网络调用。
- 填写操作应支持幂等重复执行，不重复添加多值条目或破坏用户已手动修改的内容。
- 页面动态更新后应重新校验字段是否仍存在，禁止对过期 DOM 引用执行导航。
- 所有持久化结构带 schema 版本并可迁移。

### 10.4 可维护性与可测试性

- 核心字段模型、识别引擎、站点适配器和 UI 分层设计。
- 为字段归一化、映射优先级、敏感字段判断、最终提交保护和加密备份提供自动化测试。
- 使用虚构招聘页面夹具测试适配器；真实网站验证结果单独记录日期和浏览器版本。
- 网站规则失败时提供不含个人数据的诊断导出，便于 GitHub Issue 排查。

## 11. 权限原则

1. 使用最小权限原则，尽量通过用户主动操作的当前页面权限完成通用填写。
2. 需要持续支持的招聘域名使用可选站点权限，由用户明确授权。
3. 不请求与功能无关的浏览历史、下载记录或全局网络访问权限。
4. 每项扩展权限必须在 README 和隐私说明中解释用途。

## 12. 验收标准

### 12.1 档案与文件

- 可创建至少“雷达岗位”和“Agent 开发岗位”两个档案，共享基本信息并使用不同简历 PDF。
- 切换档案后，页面预览、答案匹配和附件推荐同步切换，不出现跨档案串用。
- PDF / DOCX 解析结果未经确认不会写入档案。
- 高敏感资料锁定后不可读取，备份默认加密。

### 12.2 表单填写

- 在测试夹具中正确处理文本、文本域、单选、多选、下拉、日期和文件上传提示。
- 对支持字段正确触发页面事件，并保留用户填写后主动修改的值。
- 未知必填项会阻止进入下一步并明确提示。
- 高敏感项每次单独确认。
- 在最终提交按钮测试集合中实现 100% 不主动点击；任何不确定按钮均停止。

### 12.3 AI

- 未配置 AI 时核心流程可正常完成。
- AI 调用前可查看数据范围，高敏感字段不会进入请求。
- AI 返回内容只作为候选，用户确认后才写入。
- AI 失败可安全降级且不丢失页面已填写内容。

### 12.4 投递记录

- 到达或点击最终提交区域不会触发自动提交。
- 用户完成提交后需再次确认才记录为已投递。
- 记录能关联到公司、岗位、职位链接和实际使用的求职档案。

### 12.5 网站兼容

- 建立版本化兼容矩阵，对每个重点目标标记状态、验证日期、已支持能力和已知限制。
- 已验证网站达到本 PRD 的常见重复字段覆盖与准确率目标。
- 无法访问的登录后页面不得虚假标记为“已验证”；需用户后续提供当期网址、脱敏页面信息或协助本地验证。

## 14. 风险与应对

| 风险                       | 应对方式                                                       |
| -------------------------- | -------------------------------------------------------------- |
| 招聘网站频繁改版           | 核心与适配器解耦、兼容矩阵、夹具回归测试、社区贡献机制         |
| 网站自定义组件无法通用填写 | 专用适配器、正确触发事件、失败时提供手动映射和半自动提示       |
| 浏览器限制文件输入         | 在允许时自动匹配；受限时定位上传区并让用户确认选择             |
| 登录、验证码和反自动化机制 | 不绕过；由用户登录和验证，插件只处理当前已授权页面             |
| AI 泄露隐私或生成错误事实  | 数据范围预览、敏感字段硬性排除、事实约束、人工确认、可完全关闭 |
| 用户忘记主密码             | 明确不可恢复提示、鼓励加密备份，不设置后门或云端找回           |
| 目标网站过多导致首版失控   | 通用引擎优先、按底层 ATS 复用、分级验证、分阶段发布            |

## 15. 开发阶段所需用户协作

1. 网站适配阶段提供当期真实招聘入口网址；若页面必须登录，可提供脱敏截图、脱敏 DOM 夹具，或由用户按测试清单在本机验证。
2. 真实简历无需加入仓库。开发和自动化测试使用虚构数据，用户的两份 PDF 只通过插件本地导入验证。
3. GitHub 发布阶段需要用户提供目标仓库地址，并在本机完成必要的 GitHub 身份认证或授权。
4. 若目标网站改变服务条款或明确禁止相关自动化行为，需重新评估该适配器的发布方式。

## 16. 已确认决策

- Chrome 与 Edge 均需支持。
- 支持手动录入和 PDF / DOCX 简历解析。
- 公共个人信息由多个求职档案复用；求职档案数量不设为固定两份。
- 当前核心档案为“雷达岗位”和“Agent 开发岗位”。
- 支持答案库、附件库、求职档案推荐、AI JD 分析和投递记录。
- 允许自动填写并安全进入下一步，不允许自动最终提交。
- 所有资料默认本地保存，高敏感内容加密且不发送给 AI。
- AI 使用用户自行配置的 OpenAI 兼容接口，且为可选功能。
- 提供中英文界面并识别中英文招聘字段。
- 默认导出加密备份，可在明确风险提示后导出未加密数据。
- 项目公开发布到 GitHub，采用 MIT License，仓库不包含真实个人数据。
